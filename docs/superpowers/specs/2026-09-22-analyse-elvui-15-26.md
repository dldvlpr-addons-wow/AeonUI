# ElvUI 15.26 : analyse et plan pour faire mieux

> Source : `/Users/dldvlpr/Downloads/elvui-15.26`, lu le 2026-09-22 (lecture seule, aucun code repris :
> licence ElvUI restrictive). Quatre passes d'analyse (cœur, cadres, barres et sacs, chat et divers),
> points clés revérifiés dans le code.

## 1. Structure

- **Trois addons obligatoires** : `ElvUI` (cœur), `ElvUI_Libraries` (Ace3, oUF, LibActionButton, LibSharedMedia, LibCustomGlow, LibDispel, LibSimpleSticky, LibDualSpec, TaintLess…), `ElvUI_Options` (chargé à la demande).
- **Un toc par version de jeu** : Mainline `120100` (Midnight, même moteur que Forever), Mists `50504`, Wrath `38002`, TBC `20506`, Vanilla `11509`. **Aucun toc `16001` ni `_Camelot` : ElvUI ne se charge pas sur Forever.**
- **Découpage** : `Game/Shared` (70 800 lignes de code commun) + `Game/<Version>` (skins, filtres, data texts propres à une version). 730 fichiers Lua, environ 219 000 lignes au total.
- **Espaces de noms** : `E` (addon Ace3), `L` (langue), `V` (réglages par personnage, `ElvPrivateDB`), `P` (profil, `ElvDB`), `G` (compte). Defaults de profil : 3 862 lignes.
- **Modules** : `E:RegisterModule` + initialisation sous `xpcall`, même isolation que ForeverUI.
- **Profils** : AceDB. Un changement de profil par personnage recharge toute l'interface. Profil par spécialisation (LibDualSpec), absent en Classic pur.

## 3. Ce que le moteur Midnight permet, vu chez ElvUI

ElvUI Mainline tourne sur le même moteur 12.x que Forever. Ces API sont la vraie leçon à reprendre (mécanismes, pas code) :

| API | Usage ElvUI | Chez ForeverUI |
|---|---|---|
| `C_StringUtil.CreateNumericRuleFormatter`, `cooldown:SetCountdownFormatter`, `SetBreakpoints`, `SetCountdownAbbrevThreshold`, `SetMinimumCountdownDuration` | Texte de recharge coloré par palier, sans lire la durée | Absent |
| `SetCooldownFromDurationObject` | Recharges des barres et des auras | Barres seulement |
| `UnitHealthPercent(unit, true, curve)` + courbe de couleurs | Couleur de vie en dégradé malgré le secret | Pourcentage seulement |
| `frame:SetAlphaFromBoolean(inRange, a, b)` | Portée sans tester un booléen secret | `UnitInRange` testé en Lua, abandon si secret |
| `C_Secrets.ShouldUnitIdentityBeSecret`, `canaccessvalue`, `issecrettable`, `CanCompareUnitTokens` | Gardes avant de lire ou comparer une unité | `issecretvalue` seul |
| `GetActionCount` coupé sur Midnight | Nombre de charges non lisible | À vérifier sur nos boutons |

Tout est à confirmer sur Forever par `/fui diag` avant usage, avec un repli quand l'API manque.

## 4. Où ElvUI est faible

1. **Il ne tourne pas sur Forever.** Pas de toc 16001, et la branche Vanilla vise 11509 sans valeurs secrètes.
2. **Poids** : trois addons, une vingtaine de bibliothèques, 219 000 lignes, beaucoup de code mort en Classic (spés, M+, Warband, Azérite).
3. **Persistance** : rien pour contourner la relecture des SavedVariables sur Forever. ForeverUI a la seule persistance validée en jeu.
4. **Habillage fragile** : un fichier par cadre Blizzard, repositionné élément par élément, qui casse à chaque patch.
5. **Secrets inégaux** : puissance marquée « what do i do here? » dans oUF, menace et portée sans garde ; une valeur secrète efface la ligne sans le dire.
6. **Complexité** : milliers d'options, courbe d'apprentissage lourde, première ouverture des options qui fige le jeu.
7. **Plaques** : plus de filtres de style (déclencheur et action) dans cette version.
8. **Français** : traduction communautaire. ForeverUI est écrit en français.

## 5. Faire mieux : ordre proposé

Chaque étape est livrable et publiable seule, dans l'esprit du cadrage v2.

1. **Étape 10, secrets et recharges** : texte de recharge par formateur natif (paliers et couleurs, repli sur la CVar), portée par `SetAlphaFromBoolean`, couleur de vie par courbe, gardes `ShouldUnitIdentityBeSecret` et `canaccessvalue` dans `Core/Compat.lua`, ligne `/fui diag` pour chaque API.
2. **Étape 11, textes et filtres** : formats de texte par cadre (un petit jeu de jetons, pas 90 tags), filtres d'auras (liste blanche, liste noire, boss, dissipables, les miens) partagés par cadres, plaques et groupe.
3. **Étape 12, indicateurs de groupe** : prêt, résurrection, invocation, prédiction de soins si l'API répond, portrait optionnel, menace en bordure ou lueur, cadres tanks et assistants.
4. **Étape 13, filtres de style des plaques** : règles « si (cible, santé < x, incante, quête, élite…) alors (couleur, taille, lueur, masquer) ». ElvUI n'en a plus : c'est un vrai différenciateur.
5. **Étape 14, panneaux de données** : panneaux libres sur les movers, la barre du haut devient un panneau, data texts ajoutés (coordonnées, quêtes, régénération, vitesse, DPS natif si `C_DamageMeter` répond).
6. **Étape 15, chat et butin** : historique conservé au /reload, mots-clés avec son, anti-spam tolérant (texte normalisé), fenêtre de jets de butin, fenêtre de butin.
7. **Étape 16, raid** : utilitaire de raid (prêt, rôles, compte à rebours, marqueurs), niveau d'objet en inspection dans l'infobulle et l'inspection.
8. **Étape 17, sacs** : tout-en-un léger (recherche, tri Blizzard, niveau d'objet, gris en surbrillance), sans le code Retail.
9. **Transverse** : recherche dans les options, envoi de profil au groupe par messages d'addon, coordonnées et molette sur les movers.

Garder en toutes étapes : Lua pur, un seul toc, persistance maison, cession à ElvUI, tests headless, français natif.
